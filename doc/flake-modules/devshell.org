#+title: flakeModules.devshell

~devshell~ is a ~flake-parts~ module for projects that use ~devshell~[fn:1].

It extends upstream ~devshell~ entries with generated files linked into the
project when the shell starts.

The module is configured under ~perSystem.devshells~. Each
~perSystem.devshells.<name>~ entry is still an upstream devshell module, so normal
options such as ~devshell.packages~, ~commands~, ~env~, and ~devshell.startup~ remain
available.

For each configured shell, the module also exposes the final shell at the
standard flake output path ~devShells.${system}.<name>~.

* Installation

If your flake already imports this repository as an input and exports
~flakeModules.devshell~, add it to ~imports~ in the usual ~flake-parts~ style.

The module requires a ~devshell~ input.

#+begin_src nix
  {
    inputs = {
      devshell.url = "github:numtide/devshell";
      flake-parts.url = "github:hercules-ci/flake-parts";
      infix.url = "git+https://codeberg.org/bingshan/infix.git?ref=main";
    };

    outputs =
      inputs@{
        flake-parts,
        infix,
        ...
      }:
      flake-parts.lib.mkFlake { inherit inputs; } {
        imports = [
          infix.flakeModules.devshell
        ];

        systems = [
          "x86_64-linux"
        ];
      };
  }
#+end_src

After that, configure shells under ~perSystem.devshells~.

* Quick Start

The smallest useful configuration defines one upstream devshell:

#+begin_src nix
  {
    perSystem =
      { pkgs, ... }:
      {
        devshells.default = {
          devshell = {
            name = "example";

            packages = with pkgs; [
              git
              ripgrep
            ];
          };
        };
      };
  }
#+end_src

This creates ~devShells.${system}.default~ from
~perSystem.devshells.default.devshell.shell~.

* Generated Files

Use ~perSystem.devshells.<name>.files~ to generate store files and link them into
the project at shell startup.

#+begin_src nix
  {
    perSystem =
      { pkgs, ... }:
      let
        json = pkgs.formats.json { };
        toml = pkgs.formats.toml { };
      in
      {
        devshells.default = {
          files = {
            treefmt = {
              path = "treefmt.toml";

              generator =
                data:
                toml.generate "treefmt.toml" data;

              data = {
                formatter = {
                  nixfmt = {
                    command = "nixfmt";

                    includes = [
                      "*.nix"
                    ];
                  };
                };
              };

              packages = with pkgs; [
                nixfmt
                treefmt
              ];
            };

            editor-settings = {
              path = ".config/example/settings.json";

              generator =
                data:
                json.generate "example-settings.json" data;

              data = {
                formatter = "treefmt";
                language = "nix";
              };

              deps = [
                "treefmt"
              ];
            };
          };
        };
      };
  }
#+end_src

Each file entry becomes a devshell startup entry with the same name. In the
example above, ~editor-settings~ depends on the ~treefmt~ startup entry.

Packages declared under a file entry are collected into ~devshell.packages~. This
makes tools needed by file hooks available in the development shell.

* Complete Example

The following example combines generated files, packages, hooks, and startup
ordering:

#+begin_src nix
  {
    perSystem =
      { pkgs, ... }:
      let
        json = pkgs.formats.json { };
        yaml = pkgs.formats.yaml { };
      in
      {
        devshells.agent-workspace = {
          devshell = {
            name = "agent-workspace";

            packages = with pkgs; [
              jq
              nil
              ripgrep
            ];
          };

          files = {
            agent-routing = {
              path = ".agents/config/routing.yaml";

              generator =
                data:
                yaml.generate "agent-routing.yaml" data;

              data = {
                default_agent = "codex";

                tools = {
                  commit = "infix/commit";
                  nix = "bingshan/nix-refactor";
                  openai_cli = "openai/cli-creator";
                };
              };

              packages = with pkgs; [
                yq
              ];

              hook = ''
                ${pkgs.yq}/bin/yq '.tools' \
                  "$PRJ_ROOT/.agents/config/routing.yaml" >/dev/null
              '';
            };

            codex-settings = {
              path = ".codex/settings.json";

              generator =
                data:
                json.generate "codex-settings.json" data;

              data = {
                model = "gpt-5.5";
                reasoning_effort = "medium";
              };

              deps = [
                "agent-routing"
              ];
            };
          };
        };
      };
  }
#+end_src

This configuration produces these effects:

- ~.agents/config/routing.yaml~ and ~.codex/settings.json~ are generated from
  structured Nix data.
- generated files are linked under ~$PRJ_ROOT~ when the shell starts;
- ~codex-settings~ depends on the ~agent-routing~ startup entry;
- packages declared by file entries are available in the devshell;
- the file hook validates the generated routing file when startup runs.

* Startup Ordering

The module creates devshell startup entries for files.

File startup entries use the same name as the file entry:

#+begin_src nix
  files.treefmt = {
    # ...
  };
#+end_src

This creates a startup entry named ~treefmt~.

File entries can depend on other devshell startup entries:

#+begin_src nix
  files.codex-settings = {
    deps = [
      "agent-routing"
    ];

    # ...
  };
#+end_src

* What The Module Manages

For each ~perSystem.devshells.<name>~ entry, the module can manage:

- the standard upstream devshell configuration;
- generated project files declared under ~files~;
- packages required by file entries;
- the standard ~devShells.${system}.<name>~ flake output.

Generated files are linked with ~ln -sfnT~. This updates the exact destination
path and can replace an existing file or symbolic link at that path.

* Option Reference

** ~perSystem.devshells~

Type: ~AttrSet String Submodule~.

Main configuration entry for named devshells.

Each entry is an upstream ~devshell~ module extended with the ~files~ option
documented below.

Default: ~{ }~.

** ~perSystem.devshells.<name>.files~

Type: ~AttrSet String Submodule~.

Generated files linked into the project when entering the shell.

Default: ~{ }~.

*** ~perSystem.devshells.<name>.files.<file>.data~

Type: ~Anything~.

Structured data passed to ~generator~.

*** ~perSystem.devshells.<name>.files.<file>.deps~

Type: ~[String]~.

Startup entries that must run before this file is linked.

Default: ~[ ]~.

*** ~perSystem.devshells.<name>.files.<file>.generator~

Type: ~Function~.

Function that turns ~data~ into a generated store file.

Typical generators come from ~pkgs.formats~, for example ~(pkgs.formats.json {
}).generate~.

*** ~perSystem.devshells.<name>.files.<file>.hook~

Type: ~Lines~.

Extra shell hook appended after linking this file.

Default: ~""~.

*** ~perSystem.devshells.<name>.files.<file>.packages~

Type: ~[Package]~.

Packages needed by the generated file or hook.

Default: ~[ ]~.

All packages from file entries are added to the devshell package list.

*** ~perSystem.devshells.<name>.files.<file>.path~

Type: ~String~.

Project-root-relative path for the linked generated file.

The path must not start with ~/~.
